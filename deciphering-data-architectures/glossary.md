# Glossary

- **ACID** — Atomicity, Consistency, Isolation, Durability; transaction reliability properties. Delta Lake supports them per single table (Ch 12)
- **Aggregated domain data** — analytical data combining/aggregating data from multiple domains, usually for query performance (Ch 13)
- **Analytical data** — a transformed historical view of operational data, used for reporting, visualization, and ML (Ch 7)
- **Architecture Design Session (ADS)** — a structured, vendor-neutral workshop producing an architecture blueprint and action plan (Ch 3)
- **Batch processing** — grouping transactions and processing them at scheduled intervals (Ch 9)
- **Bottom-up approach** — collecting data before forming hypotheses, exploring to surface questions (Ch 5)
- **Business intelligence (BI)** — collecting, analyzing, and using data to make more informed decisions (Ch 1)
- **Change data capture (CDC)** — reading a database transaction log to identify changed rows for near-real-time warehousing (Ch 4)
- **Common Data Model (CDM)** — a standardized, industry-tailored schema so any source maps to a common language (Ch 8)
- **Conformed dimension** — a dimension standardized across multiple fact tables for consistent reporting (Ch 8, Ch 14)
- **Consumer-aligned domain data** — analytical data transformed to fit specific consumers/use cases (Ch 13)
- **Data contract** — the producer/consumer agreement defining data format, schema, transformation, and access (Ch 13)
- **Data fabric** — an MDW plus technologies (catalog, MDM, virtualization, real-time, APIs) to consume any data (Ch 11)
- **Data federation** — integrating data from disparate sources without physical consolidation (Ch 6, Ch 13)
- **Data governance** — policies and procedures for collecting, storing, securing, transforming, and reporting data (Ch 9)
- **Data hub** — a centralized system for ingesting, integrating, and distributing data between systems (Ch 6)
- **Data lake** — object storage for raw data in its natural format, schema-on-read (Ch 5)
- **Data lakehouse** — a single repository (Delta-Lake-enabled lake) replacing the RDW (Ch 12)
- **Data lineage** — the recorded history of a piece of data: origin, transformations, storage (Ch 11)
- **Data mart** — a department-focused subset of the warehouse (Ch 6)
- **Data mesh** — a decentralized concept based on Dehghani's four principles (Ch 13)
- **Data product** — a self-contained, independently deployable unit of data delivering business value (Ch 13)
- **Data quantum** — Dehghani's unit encapsulating data + metadata + code + policy + infrastructure; no real technology yet (Ch 14)
- **Data swamp** — an unorganized, unmanageable data lake (Ch 5)
- **Data vault** — a modeling methodology of hubs, links, and satellites (Ch 8)
- **Data virtualization** — a logical, non-replicating view over multiple sources (Ch 6)
- **Delta Lake** — a transactional storage layer (Parquet + transaction log) adding RDW-like features to a lake (Ch 12)
- **Dimensional modeling** — facts (measures) + dimensions (attributes), denormalized for analysis (Ch 8)
- **Domain ownership** — Dehghani's principle #1: the operational domain closest to the data owns the analytical data (Ch 13)
- **Domain-Driven Design (DDD)** — designing a domain-oriented architecture (Ch 13)
- **ELT / ETL** — Extract-Load-Transform (transform in place) vs. Extract-Transform-Load (transform in flight) (Ch 9)
- **Enterprise Data Warehouse (EDW)** — a DW used by the whole organization (Ch 4)
- **Federated computational governance** — Dehghani's principle #4: central standards, domain implementation (Ch 13)
- **Federated query** — a single query spanning multiple sources, combined into one result set (Ch 6)
- **Hadoop** — OSS framework (HDFS + MapReduce) for distributed batch processing (Ch 16)
- **HDFS** — Hadoop Distributed File System; splits data into blocks across nodes (Ch 16)
- **Kappa architecture** — stream-only processing with a single event stream (Ch 7)
- **Lambda architecture** — dual batch + stream processing with a unified serving layer (Ch 7)
- **Master Data Management (MDM)** — creating one "golden" master record per entity across sources (Ch 6)
- **Massively parallel processing (MPP)** — scale-out: many servers each with their own memory/disk (Ch 7)
- **Modern Data Warehouse (MDW)** — RDW + data lake side by side (Ch 10)
- **Normalization (1NF/2NF/3NF)** — decomposing tables to minimize redundancy and dependency (Ch 8)
- **OLAP** — online analytical processing; fast read-heavy analysis via cubes/tabular models (Ch 7)
- **OLTP** — online transaction processing; CRUD operations with low latency (Ch 7)
- **Operational data** — real-time data used to run day-to-day operations (Ch 7)
- **Operational Data Store (ODS)** — an enterprise-wide, near-real-time view of operational data (Ch 6)
- **Parquet** — a columnar file format optimized for big-data processing (Ch 5)
- **Polyglot persistence** — using multiple storage technologies, each matched to its data type (Ch 7)
- **Predictive / prescriptive analytics** — forecast what will happen vs. suggest actions to affect outcomes (Ch 5)
- **Relational Data Warehouse (RDW)** — centralized structured data for historical/trend analysis (Ch 4)
- **Reverse ETL** — moving warehouse data back into operational/SaaS systems (Ch 9)
- **Schema-on-read / schema-on-write** — apply schema at read vs. define schema before data lands (Ch 2)
- **Self-service BI** — nontechnical users building their own reports without IT (Ch 1)
- **Single Version of Truth (SVOT)** — a unified, consistent, standardized view of all data (Ch 4)
- **Six Vs** — Volume, Variety, Velocity, Veracity, Variability, Value (Ch 1)
- **Slowly changing dimension (SCD)** — Type 1 overwrite, Type 2 version history, Type 3 full records (Ch 8)
- **Source-aligned domain data** — analytical data mirroring its operational source (Ch 13)
- **Spreadmart** — an informal spreadsheet-based data mart (Ch 1)
- **Star schema** — a central fact table surrounded by dimension tables (Ch 8)
- **Symmetric multiprocessing (SMP)** — scale-up: multiple processors sharing disk/memory in one server (Ch 7)
- **Surrogate key** — an artificial generated primary key used in dimensional models (Ch 8)
- **Top-down approach** — planning/design first, then building (Ch 4)
- **Z-order** — a data-indexing technique (Morton order) used in Delta Lake for fast access (Ch 12)
