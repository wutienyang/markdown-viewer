# Glossary — ByteByteGo Interview Prep

Definitions are grouped by book, alphabetized within each group. Chapter refs use `book/slug`.

## System Design Interview

- **Bloom filter** — probabilistic space-efficient set-membership test (system-design/09)
- **CDN** — geographically dispersed edge servers caching static content close to users (system-design/02)
- **Delta sync** — sync only modified file blocks to cut bandwidth (system-design/16)
- **Double-entry ledger** — every debit matched by a credit; sum of entries = 0 (system-design/27)
- **Erasure coding** — chunk + parity redundancy for high durability at lower storage cost (system-design/25)
- **Event sourcing** — persist an immutable event log as source of truth; replay to rebuild state (system-design/28)
- **Fanout on write/read** — push posts at write time vs pull at read time (system-design/12)
- **Geohash** — 1D base32 encoding of lat/lng grids for spatial indexing (system-design/17)
- **GOP** — independently playable chunk of frames enabling parallel upload (system-design/15)
- **ISR (in-sync replicas)** — replicas caught up with the leader within a lag threshold (system-design/20)
- **Long-tail distribution** — few popular videos dominate; serve only popular from CDN (system-design/15)
- **Merkle tree** — hash tree to sync only differing replica buckets (system-design/07)
- **Peak QPS** — roughly 2× average QPS as a working rule (system-design/03)
- **Quorum** — W write acks / R read responses out of N replicas; W+R>N ⇒ strong consistency (system-design/07)
- **Saga** — linear distributed transaction with compensating rollback (system-design/23)
- **Sequencer** — stamps monotonic sequence IDs to guarantee deterministic replay (system-design/29)
- **Sharding key** — column(s) deciding data distribution across shards; must distribute evenly (system-design/02)
- **SLA** — formal uptime contract, usually ≥99.9% (system-design/03)
- **Sloppy quorum / hinted handoff** — use first W/R healthy nodes; hand data back when a node returns (system-design/07)
- **Snowflake** — 64-bit ID: sign·timestamp·datacenter·machine·sequence (system-design/08)
- **Sorted set** — Redis data type (hash + skip list) for O(log n) ranking (system-design/26)
- **Token bucket** — capacity + refill rate; each request consumes a token; permits bursts (system-design/05)
- **Transcoding** — converting video into compatible formats/bitrates (system-design/15)
- **Trie** — prefix tree with per-node frequency and cached top-k (system-design/14)
- **Vector clock** — [server, version] pairs detecting ancestor vs sibling (conflict) (system-design/07)
- **Virtual nodes** — multiple ring points per server to balance partitions (system-design/06)
- **Watermark** — extended aggregation window to absorb slightly late events (system-design/22)
- **WebSocket** — persistent bidirectional connection, upgraded from HTTP (system-design/13)

## Coding Interview Patterns

- **Adjacency list** — graph representation mapping each node to its neighbors (coding-patterns/13)
- **Complement** — the value `target - x` needed to pair with `x` (coding-patterns/02)
- **Deque** — a double-ended queue supporting O(1) add/remove from both ends (coding-patterns/07)
- **Dummy Node** — a sentinel prepended to a linked list to simplify head removal (coding-patterns/03)
- **Dynamic Sliding Window** — a window that expands/shrinks to satisfy a condition (coding-patterns/05)
- **Fixed Sliding Window** — a window of constant length sliding across the data (coding-patterns/05)
- **Floyd's Cycle Detection** — fast/slow pointers meeting to detect a cycle (coding-patterns/04)
- **GCD (Euclidean)** — largest common divisor, used to reduce slope fractions (coding-patterns/19)
- **Greedy choice property** — local optimum at each step yields the global optimum (coding-patterns/16)
- **Hash Set** — a set of keys enabling O(1) membership/duplicate checks (coding-patterns/02)
- **Inorder traversal** — left, node, right; yields BST values sorted (coding-patterns/11)
- **Inward Traversal** — two pointers starting at opposite ends and moving toward the center (coding-patterns/01)
- **Level-order traversal** — BFS that processes one level at a time via a `len(queue)` snapshot (coding-patterns/11)
- **Lower Bound** — the first position where a value is >= target (coding-patterns/06)
- **Min-Heap / Max-Heap** — a tree keeping the smallest/largest element on top (coding-patterns/08)
- **Monotonic Stack** — a stack kept sorted by popping order-breakers (coding-patterns/07)
- **Multi-source BFS** — BFS seeded with all sources so distance levels radiate simultaneously (coding-patterns/13)
- **Optimal substructure** — optimal solution built from optimal subproblem solutions (coding-patterns/15)
- **Overlapping Intervals** — intervals sharing at least one value; `A.end >= B.start` (coding-patterns/09)
- **Overlapping subproblems** — same subproblem solved repeatedly; memoization caches it (coding-patterns/15)
- **Partition (quicksort)** — place a pivot so smaller elements are left, larger are right (coding-patterns/17)
- **Postorder traversal** — left, right, node; children before parent (coding-patterns/11)
- **Prefix Product** — running cumulative product; init with 1 instead of 0 (coding-patterns/10)
- **Prefix Sum** — running cumulative sum up to each index (coding-patterns/10)
- **Preorder traversal** — process node, then left, then right subtree; root first (coding-patterns/11)
- **Quickselect** — partition but recurse on only one side to find the kth element in O(n) avg (coding-patterns/17)
- **State space tree** — decision tree of all possible choices explored by backtracking (coding-patterns/14)
- **Sweep Line** — processing ordered start/end events to count active intervals (coding-patterns/09)
- **Topological sort (Kahn's)** — process in-degree-0 nodes; detects cycles if nodes remain (coding-patterns/13)
- **Trie (prefix tree)** — tree storing strings by shared prefixes for O(k) prefix/search (coding-patterns/12)
- **Two Pointer** — an algorithm using two indices to traverse and compare positions in a linear structure (coding-patterns/01)
- **Two-Heap Median** — splitting a stream into smaller/larger halves via two heaps (coding-patterns/08)
- **Union-Find (DSU)** — structure supporting union + find with path compression and union-by-size (coding-patterns/13)
- **Upper Bound** — the last position where a value is <= target (coding-patterns/06)
- **Wildcard (`.`) matching** — recurse into all child branches when a `.` is encountered (coding-patterns/12)
- **XOR cancellation** — `a^a=0`, `a^0=a`; XORing all elements isolates a unique value (coding-patterns/18)

## Machine Learning System Design Interview

- **ANN (approximate nearest neighbor)** — sublinear retrieval of near-neighbors in embedding space, e.g. Faiss/ScaNN (ml/01)
- **Candidate generation** — fast coarse stage narrowing the full item corpus to a small candidate set (ml/05)
- **Contrastive training** — teach a model to pull positive pairs together and push negatives apart (ml/01)
- **Early fusion** — combine modalities before prediction to catch cross-modality signals (ml/04)
- **Edge prediction** — predict whether an edge exists between two graph nodes (ml/10)
- **Factorization Machines (FM)** — embedding-based model of all pairwise feature interactions (ml/07)
- **Feature crossing** — manual combination of features to capture interactions (ml/07)
- **GNN** — neural network operating directly on graph-structured input (ml/10)
- **mAP** — mean average precision; ranking metric for binary relevance (ml/01, ml/06)
- **Multi-task learning** — one model learns several tasks via shared + task-specific layers (ml/04)
- **nDCG** — normalized DCG; ranking metric for graded relevance (ml/01)
- **NCE** — model cross-entropy divided by background-CTR cross-entropy (ml/07)
- **Negative sampling** — pair a central item with random/dissimilar items as negative training examples (ml/08)
- **Pointwise LTR** — score each item independently, then sort (ml/06)
- **Representation learning** — training models to map inputs to embeddings where distance captures similarity (ml/01)
- **Scoring / ranking** — heavy accurate model re-ordering the candidate set by predicted relevance (ml/05)
- **Session-based recommendation** — predict next item from recent browsing rather than long-term profile (ml/08)
- **Two-tower model** — user + item encoder producing embeddings whose distance encodes relevance (ml/05)

## Generative AI System Design Interview

- **BPE** — subword tokenizer that iteratively merges frequent character pairs (genai/02)
- **CFG (classifier-free guidance)** — blend conditioned/unconditioned predictions for prompt alignment (genai/08)
- **CIDEr** — consensus-based captioning metric using TF-IDF + cosine similarity (genai/04)
- **CLIPScore** — cosine similarity of CLIP text/image embeddings (genai/08)
- **Cross-attention** — decoder attends to encoder output to align generation to input (genai/02)
- **Cross-entropy loss** — measures divergence between predicted and true token distributions (genai/01)
- **DDIM** — sampling that reduces diffusion steps (~1000 → ~20) (genai/08)
- **Diffusion model** — learns to reverse a noising process to generate data (genai/08)
- **Discriminative model** — learns P(Y|X) to classify/predict; cannot sample new data (genai/00)
- **DreamBooth** — finetune full diffusion model with rare token + prior preservation loss (genai/09)
- **Faithfulness** — whether a response is grounded in retrieved context (not hallucinated) (genai/05)
- **FID (Fréchet Inception Distance)** — distance between real/generated feature distributions (genai/06)
- **FVD (Fréchet Video Distance)** — FID extended to video via I3D features (genai/10)
- **GAN** — generator vs. discriminator adversarial framework (genai/06)
- **Generative model** — learns P(X) or P(X,Y) to sample new instances (genai/00)
- **Latent diffusion model (LDM)** — diffusion in a compressed latent space (genai/10)
- **LoRA** — low-rank ΔW = A·B adaptation, freezing original weights (genai/09)
- **MLM (masked language modeling)** — predict masked tokens; prevents encoder-decoder "cheating" (genai/02)
- **Mode collapse** — generator producing limited variety (genai/06)
- **Next-token prediction** — ML objective of predicting the following token given prior tokens (genai/01)
- **Patchify** — split an image/video into fixed patches projected to embeddings (genai/04)
- **Posterior collapse** — decoder ignores latent variables (genai/07)
- **RAG** — retrieval + generation to ground an LLM in external data (genai/05)
- **RLHF** — align model to human preferences via a reward model + PPO (genai/03)
- **RoPE** — rotary positional encoding capturing absolute + relative position (genai/03)
- **Scaling law** — power-law relationship between loss and model/data/compute scale (genai/00)
- **SFT (supervised finetuning)** — train on (prompt, response) demonstration data (genai/03)
- **Temperature** — logit scaling controlling sampling randomness (genai/03)
- **Temporal attention/convolution** — layers modeling cross-frame motion consistency (genai/10)
- **Top-p (nucleus) sampling** — sample from the smallest token set whose cumulative probability exceeds p (genai/03)
- **VQ-VAE** — VAE with a codebook quantizer for discrete image tokens (genai/07)
- **Wasserstein loss** — critic-based GAN loss stabilizing training (genai/06)

## Mobile System Design Interview

- **Adaptive bitrate streaming (ABR)** — auto-adjust video quality by network/buffer/CPU via HLS/DASH (mobile/08)
- **Block-level sync** — upload only changed file blocks rather than full copies (Dropbox Broccoli) (mobile/07)
- **Buffered updates** — collect real-time events and flush UI at fixed intervals to reduce jank/battery drain (mobile/04)
- **Cursor-based pagination** — page via a unique pointer (cursor) instead of an offset; stable on frequently-updated data (mobile/02)
- **Full-Text Search (FTS)** — SQLite indexing for fast prefix matching, tokenization, and fuzzy search (mobile/06)
- **Idempotency key** — client-supplied key (`requestId`) letting the backend de-duplicate retried requests (mobile/03)
- **Intelligent prefetching** — signal-driven (device/user/relevance) background content fetching (mobile/08)
- **JavaScript bridge** — native↔WebView channel; native handles networking/buffering, WebView renders (mobile/04)
- **Offset pagination** — skip N rows per page; simple but degrades on large/live datasets (mobile/05)
- **Optimistic concurrency control** — validate against current version before commit; reject mismatches with 409 (mobile/07)
- **Optimistic writes** — update UI immediately on user action, then persist/sync, without waiting for backend confirmation (mobile/02)
- **Reservation hold** — server-authoritative time window (≈15 min) temporarily locking a room during booking (mobile/06)
- **Resumable uploads** — chunked upload with a persisted session so interrupted transfers continue from the last chunk (mobile/07)
- **Single Source of Truth (SSOT)** — the local DB is the only data source the UI reads; Backend → Local Storage → UI (mobile/02)
- **Tokenization** — replace card data with a PSP token; store only a reference + last-4 digits (mobile/06)
- **Unidirectional Data Flow (UDF)** — data flows one direction to UI; events flow back to mutate state (mobile/09)
- **WebSocket** — full-duplex persistent protocol for server-initiated real-time messages (mobile/03)

## Object-Oriented Design Interview

- **Abstraction** — exposing what an object does while hiding how, via abstract classes/interfaces (ood/02)
- **Composite** — tree structures handled uniformly through one interface (ood/05)
- **Composition** — "has-a" relationship via contained objects; preferred over deep inheritance (ood/02)
- **Decorator** — wrap an object to add behavior without modifying it (ood/08)
- **DIP** — depend on abstractions, not concrete low-level modules (ood/02)
- **Encapsulation** — bundling private data with public methods to hide internal state (ood/02)
- **Facade** — simple interface over a complex subsystem (ood/03)
- **Inheritance** — subclass inherits from superclass ("is-a") (ood/02)
- **ISP** — clients should not depend on interfaces they don't use (ood/02)
- **LSP** — subclasses replace base classes without breaking contracts (ood/02)
- **Memento** — save/restore object state for undo (ood/09)
- **Observer** — subscribers notified on subject state change (ood/07)
- **OCP** — open for extension, closed for modification (ood/02)
- **Optimistic Locking** — verify at commit, retry on conflict; low contention (ood/04)
- **Pessimistic Locking** — lock resource upfront, release after; high contention (ood/04)
- **Polymorphism** — objects behave differently through a common interface; overloading vs overriding (ood/02)
- **SRP** — a class should have one reason to change (ood/02)
- **State** — behavior changes when internal state changes (ood/06)
- **Strategy** — interchangeable algorithms encapsulated behind one interface (ood/03)

## How to Write a Good Resume

- **ATS** — Applicant Tracking System; a coordination tool, not an automatic rejector (resume/04)
- **Boolean search** — recruiter searches using AND/OR/NOT operators (resume/12)
- **Generalist vs. specific-technology companies** — big tech screens for breadth/impact; smaller firms screen for exact stack (resume/08)
- **Journeyman resume** — a resume showing little or no career progression (resume/03)
- **Keyword stuffing** — including job-relevant keywords in a readable, non-crammed way (resume/08)
- **Knockout questions** — recruiter-set prescreening questions that filter ineligible candidates (resume/04)
- **Levels** — internal seniority bands (e.g., Google L5) job listings map to (resume/06)
- **Referral** — internal employee recommendation made before applying (resume/04)
- **Results/impact/contribution** — formula: "Accomplished {impact} as measured by {number} by doing {contribution}" (resume/08)
- **Self-rating (skill points/stars)** — a candidate-scored proficiency scale that only backfires (resume/15)
- **Top-down layout** — single-column resume read top to bottom (resume/14)
- **Two-column layout** — space-efficient but harder-to-scan resume format (resume/14)
- **Yes/Maybe/No model** — triage method hiring managers use to sort resumes into interview / backup / reject piles (resume/03)
