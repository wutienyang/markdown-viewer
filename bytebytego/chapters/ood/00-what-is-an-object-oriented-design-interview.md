# 00: What is an Object-Oriented Design Interview

## Core Idea
OOD interviews test your ability to model real-world or abstract systems as objects with clear roles, responsibilities, and interactions — prioritizing clean, maintainable, extensible code over a single optimal algorithm.

## Design Framework / Approach
Shift your mindset from algorithm interviews: focus on **quality, not speed**; design with **objects, not steps**; demonstrate **OOP skills, not just answers**; and plan **extensible designs, not short-term fixes**. OOD is used by companies (Amazon, Bloomberg, Uber) alongside System Design and Behavioral interviews to separate intermediate from senior engineers.

## Key Concepts & Components
- **Product Sense**: Translate real-world needs into software using domain knowledge and user-centered decisions.
- **Systems Thinking**: Decompose a complex system into subsystems with clear roles and defined interactions.
- **Decision Making**: Anticipate future needs and balance over-engineering against oversimplification.
- **Code Quality**: Write clean, logical, maintainable code — modern OOD questions are coding-focused, not just diagrams.
- **OOP Knowledge**: Apply SOLID principles and design patterns to keep software simple and production-ready.
- **Communication**: Ask clarifying questions, drive the discussion, explain rationale, and defend solutions confidently.

## Trade-offs & Anti-patterns
- **Solving too fast**: Racing to a solution skips abstractions and decomposition — slower, cleaner code wins in OOD.
- **Step-oriented thinking**: Writing all logic in one function misses the object model — think roles and relationships instead.
- **Short-term fixes**: Designs that can't absorb future requirements cost rework; aim for minimal rework under change.

## Key Takeaways
1. Use OOD questions to demonstrate maintainable, object-centered design rather than algorithmic optimization.
2. Treat the four evaluation axes (product sense, systems thinking, decision making, code quality) as explicit scoring targets.
3. Prepare by learning OOP fundamentals, practicing high-frequency problems, and rehearsing communication out loud.
